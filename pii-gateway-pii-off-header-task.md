# Задача для AI в репозитории `api.vega.chat`: заголовок `X-Vega-Pii: off` — отключение PII-щита по выбору пользователя

Клиент (репозиторий `getoffice`, officevega) добавил пользовательский переключатель
«Анонимизация персональных данных» (настройки + интерактивный бейдж щита в панели AI).
По умолчанию защита включена; когда пользователь её выключает, клиент начинает слать
на **все** запросы к `api.vega.chat` заголовок:

```
X-Vega-Pii: off
```

Шлюз должен понимать этот заголовок и пропускать такие запросы **без обезличивания**.
Без заголовка поведение не меняется: щит включён для ключей `officevega` как сейчас.

## Контракт

| Что                | Значение                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Заголовок          | `X-Vega-Pii: off` (регистр значения не важен; единственное отключающее значение — `off`)                                                                                                                                                                                                                                                                 |
| Область            | все маршруты под щитом: `chat/completions`, `responses`, `messages`, `completions`, `embeddings`, `images`, `/api/alpha/decisions` (см. `pii-gateway-followup-task.md`), а также `models` и auth/account-маршруты (`/api/auth/device/*`, `/api/v1/keys/*`, `/api/v1/account`) — там щит не применяется, но заголовок надо просто игнорировать без ошибок |
| По умолчанию       | заголовок отсутствует → щит работает как сейчас (fail-closed включён)                                                                                                                                                                                                                                                                                    |
| С заголовком `off` | маскирование/обезличивание для этого запроса не выполняется, запрос идёт к модели с исходными ПДн                                                                                                                                                                                                                                                        |

## Что сделать в шлюзе

1. В конвейере PII-щита первым шагом проверять `X-Vega-Pii: off`: при наличии — миновать
   щит целиком (и маскирование запроса, и обратную подстановку в ответе).
2. Заголовок действует **только по запросу**: состояние не липнет ни к ключу, ни к сессии.
   Следующий запрос без заголовка снова обезличивается.
3. Взаимодействие с `X-Vega-Session`: при `X-Vega-Pii: off` словарь токенов сессии для
   этого запроса не создаётся и не пополняется — обезличивания нет, восстанавливать
   нечего. `X-Vega-Session` клиент может по-прежнему слать, игнорируйте его.
4. Клиентский токен-гард одновременно отключается: клиент перестаёт ставить PII system
   prompt note и перестаёт фильтровать `#TYPE_N#`-токены в потоке. То есть в ответах на
   запросы с `off` токены могут отсутствовать/приходить «сырыми» — это нормально, эхо-
   проверок на них делать не нужно.
5. `pii_shield_error` при `off` не возвращать: ни `pii_unavailable`, ни
   `pii_attachment_not_allowed` и пр. — щит для запроса не существует.
6. Значения заголовка кроме `off` (например `on`, мусор) трактовать как «щит включён» —
   fail-closed в сторону защиты.
7. Не логировать тела запросов/ответов независимо от состояния щита (уже действует).

**Изображения — вне области щита.** Картинки (webp/png/jpeg и прочие медиа)
фильтр очистки ПД должен **пропускать полностью**, не обрабатывая их вовсе,
независимо от состояния переключателя и заголовка:

- запрос, в теле которого есть изображение (multipart-части с файлами,
  `image_url`/`input_image`/`input_references`/`data:image/…` в JSON-теле,
  бинарные тела, маршруты `images/edits` с файлами), проходит к модели с
  картинками как есть — клиент может слать на него `X-Vega-Pii: off` как на
  любой другой запрос, но даже без заголовка изображения не обезличиваются;
- текстовый контент такого запроса при этом обрабатывается по обычному
  правилу: без `off` — маскируется, с `off` — идёт как есть;
- отдельных эндпоинтов под изображения клиент не делает: media-загрузки идут
  через те же `chat/completions`/`images/*` с тем же заголовочным контрактом.

## Критерии приёмки

1. `POST /api/v1/chat/completions` с ключом `officevega` и `X-Vega-Pii: off`, в `messages`
   есть ФИО/телефон: к внешней модели уходит исходный текст без `#TYPE_N#`-токенов.
2. Тот же запрос без заголовка: обезличен как раньше.
3. Чередование запросов с заголовком и без в рамках одного `X-Vega-Session`: каждый
   обрабатывается по собственному заголовку, словарь не смешивается.
4. `X-Vega-Pii: off` на `/api/alpha/decisions`: фрагменты документов уходят наружу без
   обезличивания (это явный выбор пользователя — поиск по файлам он контролирует сам).
5. Auth/device/keys/account-маршруты с заголовком не падают и не меняют поведение.
6. Ключи других имён (не `officevega`): заголовок безвреден, поведение без изменений.

## Справка: что клиент уже шлёт

- `X-Vega-Pii: off` на весь трафик к `api.vega.chat`, пока выключен переключатель в
  настройках/бейдже (чат, стриминг, web search, `models` probe, device-login, revoke,
  account, file-index decider, media-запросы с изображениями тоже).
- `X-Vega-Session` продолжает слаться как раньше — он не связан с состоянием щита.
