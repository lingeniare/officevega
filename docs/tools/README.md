# AI-инструменты: как устроены процессы

Разбор процессов работы AI-инструментов по коду репозитория. Каждый файл —
сквозной сценарий: что вызывает модель, что делает система, что видит
пользователь.

| Инструмент | Файл | Кейс |
|---|---|---|
| AI Word | [ai-word.md](ai-word.md) | генерация текстового документа |
| AI Slides | [ai-slides.md](ai-slides.md) | генерация слайд-презентации |
| AI Html | [ai-html.md](ai-html.md) | генерация одностраничного сайта |
| AI Sheets | [ai-sheets.md](ai-sheets.md) | веб-поиск данных и заполнение таблицы |

## Общая архитектура

Все четыре приложения построены на одном движке — `AgentLoop` из
`packages/agent-core/src/loop.ts` (ReAct-цикл):

```
сообщение пользователя + buildContext() (снимок документа)
  → ход модели: текст + tool calls
  → executeTool() для каждого вызова (мутации — последовательно;
    read-only вызовы могут стартовать раньше, пока модель ещё стримит)
  → результаты возвращаются в контекст → следующий ход
  → …пока модель не ответит чистым текстом
```

Ключевые свойства цикла:

- **Лимит ходов** — `DEFAULT_MAX_TURNS = 100`; при исчерпании — финальный ход
  без тулов («отвечай из того, что уже собрано»).
- **Защита от деградации** — 3 одинаковых хода подряд или 8 ходов с одними
  ошибками → принудительная остановка; до остановки модель получает одно
  предупреждение `REPEAT_NOTE`.
- **Повторы при сбоях транспорта** — пустой стрим («empty stream»,
  шлюз закрыл SSE без контента) ретраится с backoff 1s → 3s; обрыв во время
  стриминга аргументов тула — 1 повтор.
- **Компакция истории** — при превышении ~256 КБ история схлопывается в
  LLM-саммари (или механический дайджест), последние ~96 КБ остаются verbatim.
- **Снимки для отката** — `captureSnapshot(call)` вызывается перед первым
  мутирующим тулом рана → кнопка rollback в UI.
- **Контекст в user-сообщении** — `buildContext()` каждого скилла вшивает
  снимок документа в сообщение; старые снимки вытесняются маркером
  `[snapshot superseded]`, чтобы не раздувать историю.

## Скиллы

`AgentSkill` = `{ id, systemPrompt, tools[], buildContext(), executeTool(),
verifyResponse? }`. В панели приложения скиллы компонуются через
`composeSkills` — например, Sheets собирается из 5 скиллов:
`workbook` + `files` + `merge` + `search` + `image`.

| Приложение | Состав | Файл |
|---|---|---|
| Docs | `docs+files`: docs-skill + files-skill | `apps/docs/src/renderer/ai/` |
| Slides | `slides+files`: slides-skill + files-skill | `apps/slides/src/renderer/ai/` |
| Html | `html+search`: document-skill + search-skill + files-skill + intent-skill | `apps/html/src/renderer/ai/` |
| Sheets | `sheets+files`: workbook + files + merge + search + image | `apps/sheets/src/renderer/ai/` |

## Tool-less генерация (важный приём)

Длинные артефакты (текст документа, HTML-страница) **не передаются через
аргументы тула**: шлюз буферизует аргументы до конца JSON, и документный
аргумент упирается в idle-timeout («empty stream»). Поэтому тул
(`write_document`, `plan_page`) лишь передаёт план — а система делает
**отдельный запрос без тулов**, чьё тело ответа и есть артефакт, и стримит
дельты прямо в документ/превью. См. `doc-writer.ts` (Docs) и
`page-writer.ts` (Html).

## Веб-поиск

`web_search` во всех приложениях уходит через IPC в main-процесс
(`window.*Api.webSearch`) → Serper/DuckDuckGo (`packages/ai-search`); в
renderer возвращаются только title/url/snippet + опциональный direct answer.
Ошибка бэкенда явно отличается от «нет результатов», чтобы модель не
выдумывала факты.
